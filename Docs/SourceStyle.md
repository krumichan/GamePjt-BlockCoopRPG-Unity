직접 관리하는 Unity 클라이언트·에디터, 공통 모듈, 독립 게임 서버, 계정·저장 API에 적용합니다.

直接管理する Unity クライアント・Editor、共通モジュール、独立ゲームサーバー、アカウント・保存 API に適用します。

- 들여쓰기는 공백 4칸을 사용합니다. 중괄호는 다음 줄에 여는 Allman 방식을 사용합니다.
- `if`, `else`, 반복문, `using`, `lock` 본문은 한 문장이어도 중괄호를 씁니다. `else if` 연결은 유지합니다.
- 이름이 있는 함수는 블록 본문으로 정의합니다. 함수·생성자·연산자·지역 함수 사이에는 빈 줄 한 줄을 둡니다.
- 함수 안에서는 변수 준비, 입력 검증, 상태 변경, 외부 호출, 결과 반환 등 실제 처리 경계에 빈 줄 한 줄을 둡니다. 관련 변수는 같은 묶음으로 배치합니다.
- 클래스와 함수에는 한국어 또는 일본어로 역할을 설명합니다. 중요한 처리 단락에는 순서·단위·서버 권한·저장 보장 등 코드만으로 알기 어려운 의도를 적습니다.
- 단순 대입을 매번 설명하는 주석이나 구현과 다른 설명은 추가하지 않습니다. 지역 함수는 일반 `//` 주석을 사용합니다.
- 문자열, SQL, 프로토콜 필드, 직렬화 이름, `.meta` 식별자와 처리 순서를 서식 정리 때문에 바꾸지 않습니다.

- インデントはスペース 4 個とし、開き波括弧を次の行に置く Allman 形式を使います。
- `if`、`else`、ループ、`using`、`lock` の本体は 1 文でも波括弧を使います。`else if` の連結は維持します。
- 名前のある関数はブロック本体で定義します。関数・コンストラクター・演算子・ローカル関数の間には空行を 1 行置きます。
- 関数内では変数準備、入力検証、状態変更、外部呼び出し、結果返却など実際の処理境界に空行を 1 行置きます。関連変数は同じまとまりに配置します。
- クラスと関数には韓国語または日本語で役割を説明します。重要な処理段落には順序・単位・サーバー権限・保存保証などコードだけでは分かりにくい意図を書きます。
- 単純な代入を毎回説明するコメントや実装と異なる説明は追加しません。ローカル関数には通常の `//` コメントを使います。
- 文字列、SQL、プロトコルフィールド、シリアライズ名、`.meta` 識別子と処理順序は、書式整理を理由に変更しません。

```csharp
// 서버가 확인한 피해만 적용하고, 저장할 상태가 실제로 바뀐 경우에만 알립니다.
private void ApplyDamage(int damage)
{
    // 입력 검증과 상태 계산을 먼저 마칩니다.
    if (damage <= 0)
    {
        return;
    }

    int nextHealth = Math.Max(0, health - damage);
    if (nextHealth == health)
    {
        return;
    }

    // 외부 통지는 새 상태를 반영한 뒤 실행합니다.
    health = nextHealth;
    NotifyHealthChanged();
}
```

コード例のコメントの意味：サーバーが確認した damage だけを適用し、保存する state が実際に変わる場合だけ通知します。先に入力検証と state 計算を終え、外部通知は新 state を反映してから実行します。コード枠そのものは原文どおり保持しています。

루트 `.editorconfig`가 기본 편집 규칙입니다. 이번 정리에 사용하는 `Tools/SourceLayout`은 SDK에 포함된 Roslyn으로 검증 사본만 변환하는 일회성 도구입니다. 추가한 제어문 블록과 식 본문 확장을 역변환해 원래 구문·토큰을 비교하고, 실제 출력 재파싱과 문자열·주석·전처리 코드 보존도 확인합니다. 이 검증은 컴파일·플레이 테스트의 통과를 대신하지 않습니다.

ルートの `.editorconfig` が基本編集規則です。今回の整理に使う `Tools/SourceLayout` は SDK に含まれる Roslyn で検証コピーだけを変換する一時的なツールです。追加した制御文ブロックと式本体の展開を逆変換し、元の構文・トークンを比較します。実際の出力の再解析と文字列・コメント・プリプロセッサーコードの保持も確認します。この検証はコンパイル・プレイテストの合格を代替しません。
